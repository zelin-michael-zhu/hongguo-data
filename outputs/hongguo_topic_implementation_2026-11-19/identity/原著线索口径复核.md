# 三种“原著线索”及候选题的识别边界

**目录中 28 条有书名、24 条有作者的记录，来自研究工具对简介的正则抽取。** 检查本机实际使用的 drama-radar 版本并以其函数重跑 1,388 条目录简介，重建出的平台、书名、作者三栏与 CSV 逐行完全相同。28 条有书名的记录只对应 23 种非空书名字串；相同书名是否同一部作品尚未逐一消歧。由此可做“简介中明示了什么”和“抽取器是否遗漏不同写法”，不可用目录字段与原简介相互印证平台是否正确署名。[采集调用](https://github.com/SentDz/drama-radar/blob/9963122332b7bc93b508547fb6802f663afe6d43/radar/sources/hongguo/source.py#L280) · [正则与解析函数](https://github.com/SentDz/drama-radar/blob/9963122332b7bc93b508547fb6802f663afe6d43/radar/core/text.py#L65) · [目录导出逻辑](https://github.com/SentDz/drama-radar/blob/9963122332b7bc93b508547fb6802f663afe6d43/radar/analysis/exports.py#L68)

本轮另一来源为 113 个分季条目的公开业务元数据，其中 103 个剧 ID 有关联小说 ID，共 44 个不同书 ID。在按相邻季配对的统计中，57 对的前后季给出同一非空书 ID。历史 28 条有书名的剧条目与这 113 个分季 ID 交集为零。固定样本口径不同，无法由二者的非空数量推断红果改编率、所有观看者所见署名或某类作品被遗漏的比例。[本轮季条目元数据](public_season_metadata.json) · [历史目录](../../hongguo_free_pilot_2026-11-18/history/catalog.csv)

**可以成立的 S6 问题**是，在确有平台书 ID 的编号分季作品中，普通访客看到的官网作品页有多少提供可准确消歧的书名、作者或明确的原著链接？应先按系列去重，核验书 ID 对应的原作页与作者，独立标注官网实际呈现的文字、链接与位置，描述可见性和误归风险。平台后台关联 ID 不证明作品拥有改编权，也不证明片名页以可见形式公布原作。如果结果要写成“观众能否认出原作”，还需要观众实际执行查找任务与正确率；只有网页材料时，应把因变量写为“页面是否给出可核验的原作线索”。
