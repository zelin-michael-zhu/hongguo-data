# 固定队列的官网收藏追踪

主窗的 63 个前季 ID，加上按事前信息入选过的 148 个原始参照 ID，去重后固定为 207 个 ID。4 个作品在不同季对中分别承担前季与参照角色。参照资格来自当时的匹配规则，含后来缺失而未进入最终 40 对的参照。保留这些作品可研究后续缺失和留存；队列由已有归档选定，不能作新上剧的随机样本。每日榜单与详情重复访问同一日的公开页面，是两种不同的观测来源，以下结果使用详情口径。

在本目录运行。一日追踪约需数分钟，有意逐页间隔请求。脚本不需要账户、密钥或视频文件。

```bash
python3 track_detail_favorites.py
```

- [冻结名单](favorite_watchlist.csv) 一行对应一个作品。每日输出单独目录，依据上海日期建档，每个作品每日本地日最多一条采集结果。日内不覆盖已有结果；中断后继续同一命令只补未处理的 ID。已发生的请求错误留在该日记录中。进程锁避免同日并发写入，逐次保存的 JSON 可用于恢复进度。发生 401、403 或 429 时停止该批访问。
- 今日身份核验已经请求过 113 个官网详情页。采集器先复用同日共享收藏并另取未被身份核验预留的作品。待全部身份抓取结束，再用一次 `python3 track_detail_favorites.py --complete-baseline` 补齐名单中尚缺的计数。补采只针对首次身份核验未留收藏字段的个案，不向当日已有收藏的作品重复请求。今日的榜单收藏未拿来填补详情缺失。此前日期无法由今日的详情值回填。
- 记录官网页面字段 `loaderData.detail_page.seriesSocialInfo.series_favorite_count`、原始展示值、转换数值、作品 ID、详情地址及拉取时刻。独立请求另存页面哈希，共享请求保留原抓取的 UTC 时刻。原始细节只保留作品和公共计数字段。脚本另报可观测数、1,000 整倍数的比例和正数公约数。该整除性只能验证本日数字的呈现粒度，无法推出平台采用何种舍入机制。
- 同一自然日的请求有时间跨度。隔日比较须保留两日实际时刻、检查两日都有数值及采集时间差；建议在相同本地时段运行。中间空日单列，计数下降留原值，再检查字段/对象是否改变。
- 输出路径为 `detail_favorites/YYYY-MM-DD/favorites.csv`、`summary.json` 与用于恢复的 `observations.json`。名单文件有 SHA-256 校验，每日结果保留所用名单哈希。原先已发生的季对不因向前追踪获得完整的历史曝光资料。

原始身份核对使用约定的共享缓存 [detail_favorites_companion.json](detail_favorites_companion.json)。上述命令只在调用当天运行。后续观测日期须有新抓取，才会计入有效跨度。
