# 热评盲编码员说明

管理员向两人分别发送同一份 blind_270.csv 的独立副本和本说明。训练可用旧5部的公开预览。答案全部锁定前，编码员请勿对照findings、key、自动筛查、AI初判或另一人的答案。blind_id只用于提交后的合并，聚合评分属于同剧卡片；该条评论自身的评分、点赞、位置未提供。

1. 读same_work_card的剧名、简介、题材、集数、演职员与聚合评分，再阅读review_text。在function_codes多选N叙事复述/解读、G笼统好恶、T提到具体观看偏好、M自称参与制作/推广或号召支持、S自身经历、O其他。M只依据文字，不认证身份。
2. 在cue_verbatim记录可以支持偏好判断的原句。多个线索用换行逐条记录。在matching_card_clause逐行记录最接近的卡片语句；找不到直接对应可写“卡片未说明”。每一判断都须读完整简介和标签并考虑同义改写。
3. 在dimension逐行填写维度编号。D1节奏与重复，D2情感强度与关系惯例，D3结局形式，D4叙事重心与角色结构，D5人物及世界设定一致性，D6视听呈现与可访问性，D7改编和跨季关系，D8类型惯例及其他特定观看门槛。每个编号后可加简短子类。抽象“精彩”不单立维度。有多个具体线索时，将cue_verbatim、matching_card_clause、dimension三列的第k行对齐，方便后续按剧去重。同一评论同一维度出现多次只贡献一个维度。
4. strict_1_0_unknown写1、0或?。至少一个具体且卡片未含义等价表达的观看属性记1；只有泛赞、复述或愿望时记0；当作品季别不清、反讽/猜测主导而无法确定时写?。memo可解释对照与拿不准的地方。
5. extra_spoiler_1_0_unknown针对整条评论独立写1、0、?，包括strict=0的评论。相对于已有卡片，是否额外直接揭示结局方向、关键身份/关系转折或重要事件的具体结果？泛称无虐/慢热、描述质感、预告有悬念，不自动算剧透。无新揭示写0；可能只说原著/其他季、反讽、读者猜测，无法判断写?。把可能揭示的原句写入spoiler_evidence，多条逐行写。明确给出结局方向即符合，即便没有说明谁和谁在一起。
6. 仅对strict=1的评论，把spoiler_evidence指向的明确和可能剧透分句都划掉，再看剩余文字是否仍能支持至少一个原有的具体新增维度。survives_redaction填1/0/?；strict=0或?填NA。surviving_cue按“D编号＋原文片段”逐行填写每个还能保留的维度。不得自行补写原句或恢复已遮起的内容。

提交后，管理员按blind_key.csv的series_id、source_position复原顺序。分别求每剧前1、3、6、9条在三种显示条件下覆盖多少个去重D编号。完整保留用每条strict=1中的确定新增维度，整条隐藏同时要求extra_spoiler=0，局部遮挡按surviving_cue恢复维度。若一条同时有旧维度和新增维度，只在dimension列记录判为“新增”的维度，旧维度放memo。把不确定项计为阴性、再计为阳性作边界检验，保留原分母。先呈现按作品配对的描述差异，不能推断真实用户对剧透的厌恶或选择。

## 管理员如何复算

正式数据填写两份独立副本，均保留全部270个ID及初始正文和同剧卡片。D编号与原句逐行对应。若主判定为“?”，可以在dimension填写所有合理候选并对齐原句和卡片；无从限定时留空，在memo解释原因。无新增剧透的记录，把spoiler_evidence留空。明确新增且无剧透时，保留原有全部维度，在surviving_cue为每个维度填入未被遮掉的原句。保留原句和剧透证据应标到最小分句，避免互相包含。

在本目录运行以下命令。两份盲表应由不同的人完成。脚本能发现输入指向同一文件，但不能认证填写人身份。

```sh
python3 analyze_human_coding.py \
  --coder-a 编码员甲.csv \
  --coder-b 编码员乙.csv \
  --out 人工编码汇总
```

已完成共识裁定时，在上面的命令附加 `--adjudicated 裁定全表.csv`。默认使用同目录的冻结模板和位置表，可用 `--template` 和 `--key` 指定。脚本校验ID唯一、同剧1–9位置完整、文字和卡片与模板一致、证据能在原文找到、跳题规则与保留维度一致。若两份实际盲表尚空，或必填项不全，程序返回状态2，并在写文件前停止。提交一份不完整的裁定不会触发静默填补。每次运行输出到各自的目录，避免误认之前的结果。

| 输出 | 研究解释 |
|---|---|
| agreement.json | 原始两位编码员在“新增”和“额外剧透”上的三分类混淆矩阵、原始一致率、Cohen’s κ及各自未定数。κ用实际边际比例校正偶然一致，若两人都只用同一类别则为null。裁定结果不参与信度计算。 |
| rows_to_adjudicate.csv | 主标签、剧透标签、遮挡标签或维度集合有分歧的盲ID。管理员还应抽查标签相同而文字理由可能不同的条目。 |
| coverage_per_title.csv | 按作品、编码员、显示条件和前1/3/6/9个源位置，列出下界和上界的去重维度集合与数目。整评隐藏后保留原位置，不从第k条之后回补。 |
| coverage_equal_title_means.csv | 固定同一批作品作分母，各剧等权，输出平均不同维度数和至少覆盖一个维度的作品占比。甲、乙以及可选裁定版均单独呈现。 |

三种条件分别为完整评论（full_review）、隐藏整条含剧透评论（hide_whole_review）、仅遮去涉及揭示的分句（mask_revealing_clauses）。下界只计确认新增的维度。上界允许未知判断为阳性；未知记录已列出候选时只计其候选维度，完全没有可限定的候选时以D1–D8为宽上界。确定有剧透的整评在整条隐藏条件下上下界均排除。局部遮挡后能否保留维度若仍未知，上界最多取原先可能的维度。上述界限衡量编码含糊性，不能充当抽样置信区间。完整九条曲线只面向全样本表，60条试编码表可用于双方练习和冻结口径。

## 如何检查D1至D8分别编得准不准

dimension_agreement.csv按8个维度和3种显示条件输出24行。每条评论的每个维度取0（无）、1（确定有）或?（可能有，无法判定）。完整预览条件下，明确新增的评论可能只提供D1；其他七维不会自动被算作新增。其余两种条件亦按各维度在该展示下能否保留分别比较。信度仅由两人裁定前的独立结果计算。

| 字段 | 定义与用途 |
|---|---|
| n_A0_B0 至 n_A?_B? | 逐评的3×3完整混淆格。首个字符属于甲，第二个属于乙。九格相加等于该行n_reviews。 |
| agreement_three_categories、kappa_three_categories | 三类原始一致率、校正偶然一致后的κ。大量双阴性可能造成前者很高，应同时看阳性一致率。 |
| positive_agreement_determinate、n_determinate_pairs | 双方都给出0或1的评论中，阳性一致率为2×n11／(2×n11＋n10＋n01)。这是对称性指标，不把任一人当作金标准。分母为零时留空。n_determinate_pairs另报双方可判的评论数。 |
| positive_agreement_unknown_as_nonpositive | 对某方判“?”、另一方判阳性的行，另按单侧阳性计算；这是敏感性口径。只有一方或双方未知且无人明确判阳性时不改变其分母。 |
| titles_with_either_coder_positive | 入样剧中至少有一条被任一人明确判为该维度阳性的剧数。与两人实际各判了多少阳性的混淆格一同解读。 |
| positive_agreement_cluster_p025、positive_agreement_cluster_p975 | 依据完整作品重抽的阳性一致率第2.5与97.5百分位。默认按冻结样本的三层各重抽原层剧数，整部剧9条共同进入，一共2,000次，种子20261119。可在命令附加 `--strata 分层表.csv` 指定含series_id与stratum的全样本文件；自定义位置表且未给分层时整剧不分层重抽。agreement.json记录具体分层和复算参数。 |
| bootstrap_total、bootstrap_defined | 重抽次数与阳性一致率可计算的次数。仅有可定义重抽时才计算其条件百分位；当支持阳性的剧很少、可定义次数很少、区间退化或整列空白时，应同时展示分母并明确精度不足。 |

这些范围衡量在观察样本中按作品重抽的波动；作品内的九条不作为独立重复。不同季还可能共享IP和制作方，该聚类方式未消除跨作品相关。仅主标签的一致性不足以支撑多维覆盖统计。若某个维度两人很少同时识别，报告其原始混淆格，检查边界或合并相近维度，修订后用未参与修订的样本复核。
