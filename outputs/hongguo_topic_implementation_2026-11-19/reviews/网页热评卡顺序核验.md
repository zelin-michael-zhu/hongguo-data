# 30 个官网作品页的热评卡顺序

**同一次响应中，能唯一匹配的 268/270 张网页评论卡，正文在 HTML 中的位置均与数据数组位置相同。** 全部 30 页各有 9 张服务端渲染的正文卡，28 页能逐条确认共 9 个位置；另外两页各有一个位置待定。最前 3 张卡共 90 张，有 89 张通过同位置核查。因此这批数据支持研究“官网预览靠前的正文卡提供什么信息”。用户端需要横向滚动几次、何时看到某条、点击了什么，需要设备和行为层面的测量。[逐页结果与时刻](render_order_audit.csv)

| 核对内容 | 结果 |
|---|---:|
| 同次网页卡与嵌入数组，正文经标准化后唯一完整匹配 | 173 条 |
| 表情改为图片等原因无法全文匹配，但连续正文片段能在该数组中唯一定位 | 95 条 |
| 仍无法按预定规则唯一匹配 | 2 条 |
| 早先抓取的数组与本次数组九条正文及次序全同 | 17/30 页 |
| 原九条均能在新数组逐一找回，但有换序 | 9/30 页 |
| 至少一条早先正文在本次数组无法唯一找回 | 4/30 页 |
| 两次数组的前三条正文集合相同／严格次序也相同 | 29/30 页／27/30 页 |

**如何比对。** 名单为先前冻结的 30 个剧 ID。读取免登录公开官网 HTML，在内存中对同一 HTTP 响应分两路解析。一条取 `detail_page.seriesSocialInfo.reviews.reviews`，另一条忽略 script、style，仅取评论卡正文段落的文本节点及表情图片的替代文字。先消除 HTML 编码、空白和文本渲染产生的 NUL 字符，再按完整正文唯一匹配；否则要求至少一段连续 8 字以上，取到的各长片段须在参考文本中依次出现且只对应一条评论。匹配过程未使用卡片序号来消歧。最初发现换行变成 NUL 后，仅对仍有未匹配卡片的页面复查；CSV 使用该页最终一次响应。两条待定正文受短文字或表情图片替换影响，保留问号。未存储渲染 HTML、评论正文或账号信息。[采集及核对脚本](render_order_audit.py) · [冻结名单](frozen_30.csv)

旧数组采于上海时间 2026-11-19 15:25:42 至 15:26:47。本次各页最终比对响应位于 15:45:13 至 15:47:07。两个时段的排序变化可能来自展示服务、缓存、热评更新或其他机制，本次没有识别原因。该核查没有保存过去时刻的 HTML，因此过去那一次编码材料仍应称“当时返回的预览顺序”。只有本次同一响应核验过的卡片能够直接称为“当时 SSR HTML 的文档顺序”。[逐页新旧位置映射](render_order_audit.csv)
